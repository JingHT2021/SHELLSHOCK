# ShellShock Live 截图检测器设计

## 目标

常驻运行并监听热键 `R`。按下后仅截取 ShellShock Live 游戏窗口，离线识别绿色己方坦克、所有红色敌方坦克、风力数值及风向；同时生成供后续弹道计算使用的 JSON 和便于人工检查的标注图片。基准游戏分辨率为 2560×1600。

## 范围

- 输入：按下全局热键 `R` 后的 ShellShock Live 游戏窗口客户区截图。
- 输出：`result.json`、`annotated.png`。
- 仅在用户按下 `R` 后读取 ShellShock Live 窗口像素；不向游戏发送任何键盘/鼠标事件，不修改游戏文件。
- 初版采用 OpenCV + 可选 Tesseract OCR；为后续 YOLO 标注/训练保留清晰的检测结果格式。
- 检测以实际窗口像素运行；默认的颜色/面积阈值以 2560×1600 校准，并按实际窗口宽度比例缩放。

## 架构

- `detect_shellshock.py`：命令行入口，监听 `R` 和 `Esc`；通过窗口标题定位 ShellShock Live 并截取其客户区。
- `detector.py`：颜色分割、候选轮廓筛选、模板确认、风力区检测与 OCR。
- `templates/`：绿色坦克、红色坦克和风力图标的参考模板。
- `tests/`：使用提供的样本与合成图验证基础行为。

## 检测流程

1. 用户按下 `R` 时，定位标题包含 `ShellShock Live` 的窗口；找不到窗口则打印错误并跳过本次操作。
2. 截取窗口客户区，保存带时间戳的原始图像，并转换为 BGR/HSV。
3. 用绿色/红色 HSV 色域提取坦克候选，按面积、尺寸比例及图像底部位置筛选；模板匹配作为辅助置信度。
4. 在截图上方约 35% 区域寻找浅灰色风力云朵；以其右侧三角形的朝向判断 `left` 或 `right`。
5. 裁剪云朵中的数字，放大、灰度化、阈值化后由 Tesseract 以单行数字模式识别；OCR 不可用或置信度不足时返回 `null` 和明确错误。
6. 将原始截图、JSON 和标注图写入 `output/`，文件名使用同一时间戳，避免覆盖。

## 输出格式

```json
{
  "image": {"width": 2560, "height": 1600},
  "self": {"x": 1672, "y": 763, "confidence": 0.95},
  "enemies": [{"x": 1145, "y": 755, "confidence": 0.93}],
  "wind": {"value": 20, "direction": "right", "confidence": 0.90},
  "errors": []
}
```

## 错误处理

- 图像不存在或无法解码：命令以非零状态退出。
- 找不到 ShellShock Live 窗口：打印错误并等待下次按键，不进行桌面截图。
- 未发现绿色坦克、红色坦克或风力图标：对应字段为 `null`/空数组，并加入 `errors`。
- OCR 缺失或无法稳定读数：保留可视化风力区域，`wind.value` 为 `null`。

## 测试策略

- 先为 HSV 候选、方向判断、结果序列化编写失败测试。
- 再以最小实现使测试通过。
- 为窗口查找和截图提供可注入适配器，测试不会真实截取桌面或向游戏发送输入。
- 端到端测试使用完整截图，确认绿色坦克、至少两个红色坦克和右向风标可被定位；数字 OCR 允许因本机依赖缺失而单独报告。

## 后续 YOLO 路径

复用 `annotated.png` 和 JSON 作为人工校正的初始标注来源；累积不同地图、皮肤、分辨率和 UI 主题的截图后，将模型替换为 YOLO 检测器，JSON 接口不变。
